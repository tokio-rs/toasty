# Cloudflare D1

[Cloudflare D1] is a SQLite database that Cloudflare Workers access through a
binding. Toasty's D1 driver runs inside a Worker built for
`wasm32-unknown-unknown`. It speaks the same SQL dialect as the
[SQLite driver](./sqlite.md) and supports the same Rust types and queries,
with the limits listed below.

[Cloudflare D1]: https://developers.cloudflare.com/d1/

## Enabling the driver

Add the driver crate next to Toasty and the [`worker`] crate:

```toml
[dependencies]
toasty = "{{toasty_version}}"
toasty-driver-d1 = "{{toasty_version}}"
worker = { version = "0.8", features = ["d1"] }
```

Bind a D1 database to the Worker in `wrangler.toml`:

```toml
[[d1_databases]]
binding = "DB"
database_name = "my-app"
database_id = "<database id>"
```

Then pass the binding to `Db::builder` in the request handler:

```rust,ignore
use toasty_driver_d1::D1;

#[worker::event(fetch)]
async fn fetch(
    req: worker::Request,
    env: worker::Env,
    _ctx: worker::Context,
) -> worker::Result<worker::Response> {
    let mut db = toasty::Db::builder()
        .models(toasty::models!(crate::*))
        .build(D1::new(env.d1("DB")?))
        .await
        .map_err(|e| worker::Error::RustError(e.to_string()))?;

    // Run queries with `&mut db`.
}
```

D1 has no connection URL, so `Db::builder().connect(url)` does not select
this driver.

## Creating the schema

[Embedded migrations](./schema-management.md#embedding-migrations) work on
D1: the driver records applied migrations in the `__toasty_migrations` table
and applies each migration with its record in one D1 batch, so a failed
migration leaves no partial changes. `push_schema` also works and is suitable for tests.

## Limitations

- **No transactions.** D1 rejects `BEGIN`, `COMMIT`, and `SAVEPOINT`.
  `Db::transaction` returns an unsupported-feature error. Toasty runs
  statements that need more than one query, such as a create with nested
  associations, as separate queries. If a later query fails, the earlier
  ones stay applied.
- **Integers up to 2^53 - 1.** D1 moves numbers between SQLite and the Worker
  as JavaScript numbers and does not accept `BigInt`. Binding or reading an
  `i64` or `u64` larger than `2^53 - 1` in magnitude returns an error.
- **100 bound parameters per query.** D1 rejects a query with more than 100
  parameters. Inserting many rows in one `create_many` can exceed this
  limit; split the rows into smaller groups.
- **No query events.** The driver does not emit the `toasty::query` tracing
  event, because `std::time::Instant` is not available on
  `wasm32-unknown-unknown`.
- **No pool health checks.** Workers have no timer that Toasty can use, so
  the pool ignores `pool_health_check_interval`.
