1//! Attaches guards to plan nodes. A guard is a condition on a node; when the
2//! condition is false at execution time, the node is skipped (see `exec::If`).
3//!
4//! # Why guards exist
5//!
6//! A plan often contains nodes whose output only matters when an earlier node
7//! returned rows. Consider loading todos together with each todo's user:
8//!
9//! ```text
10//! n0: query todos
11//! n1: extract the user ids from n0's rows
12//! n2: query users whose id is in n1
13//! n3: map over n0's rows, attaching each todo's user from n2
14//! ```
15//!
16//! When n0 returns no rows, the map in n3 iterates zero times, so nothing
17//! ever reads n2 — the user query is a wasted database round-trip. This pass
18//! guards n1 and n2 with the condition "n0 returned at least one row"
19//! (`non_empty(n0)`). At execution time, when n0 comes back empty, n1 and n2
20//! are skipped.
21//!
22//! # The two rules
23//!
24//! A node may be skipped only when nothing reads its output. Two rules prove
25//! that:
26//!
27//! 1. A node read [`InputRead::PerRowOf`]`(X)` — only while iterating node
28//!    X's rows — gets guard `non_empty(X)`. Iterating zero rows never reads
29//!    the input, so the node's output goes unread whenever X is empty. This
30//!    is how n2 gets its guard above: n3 is a per-row `Eval` over n0, and n2
31//!    is one of its other inputs.
32//!
33//! 2. A node whose consumers all carry guard `non_empty(X)` inherits that
34//!    guard. Whenever X is empty, every consumer is skipped, so the node's
35//!    output goes unread too. This is how n1 gets its guard: its only
36//!    consumer, n2, is guarded on n0.
37//!
38//! # When a node gets no guard
39//!
40//! The analysis is conservative: one consumer that might read the output
41//! kills the guard, and the node always executes. In particular:
42//!
43//! - A node that writes to the database (`Operation::is_effectful`) is never
44//!   skipped, and never propagates a guard to its inputs.
45//! - The completion node's output is the query result; the engine reads it
46//!   unconditionally.
47//! - Consumers guarded on different nodes disagree, so their shared input
48//!   gets no guard.
49//!
50//! In the example, n0 stays unguarded: n3 reads it as the row input
51//! ([`InputRead::Always`]), and n3 itself has no guard.
52//!
53//! # How the pass runs
54//!
55//! The pass keeps one [`Consumption`] value per node. It summarizes how the
56//! consumers visited so far read that node's output, and is one of three
57//! states: no consumer visited yet ([`Consumption::None`]), every consumer
58//! so far reads the output only when node X returned rows
59//! ([`Consumption::OnlyUnder`]`(X)`), or some consumer reads the output
60//! regardless ([`Consumption::Observed`]).
61//!
62//! The pass visits nodes in reverse execution order. A node always executes
63//! before its consumers, so the reverse walk visits every consumer first,
64//! and a node's [`Consumption`] is complete by the time the walk reaches
65//! it. Visiting a node does two things:
66//!
67//! 1. Decide the node's guard from its own [`Consumption`]: when every
68//!    consumer reads the output only when X returned rows, the node gets
69//!    guard `non_empty(X)`.
70//!
71//! 2. Update the [`Consumption`] of each input the node reads, from the
72//!    operation's declared [`InputRead`]s. A [`PerRowOf`](InputRead::PerRowOf)
73//!    input contributes "read only when the iterated node returned rows"
74//!    (rule 1). An [`Always`](InputRead::Always) input is read whenever the
75//!    node itself runs, so it contributes the node's own `non_empty` guard —
76//!    or "read regardless" when the node has none (rule 2).
77//!
78//! In the example, the walk visits n3, n2, n1, n0. n3 declares n2 as
79//! `PerRowOf(n0)`, so visiting n3 sets n2's [`Consumption`] to "read only
80//! when n0 returned rows". Visiting n2 turns that into guard `non_empty(n0)`,
81//! and — since n2 now carries that guard — sets n1's [`Consumption`] to the
82//! same state. Visiting n1 turns it into the same guard.
83//!
84//! The pass runs once, at `LogicalPlan::new`, after planning has produced
85//! the complete graph. Guards cannot be assigned earlier, while statements
86//! are still being planned: a guard is only valid if every consumer agrees,
87//! and planning may still add a consumer that reads the node
88//! unconditionally.

94/// The merge, over a node's already-visited consumers, of how each one
95/// consumes the node's output.
96#[derive(Clone, Copy)]
97enum Consumption {
98    /// No consumer visited yet.
99    None,
100
101    /// Every consumer so far is unobservable when the referenced node's
102    /// output is empty.
103    OnlyUnder(NodeId),
104
105    /// Some consumer observes the output unconditionally, or consumers
106    /// disagree on the condition; the node must always execute.
107    Observed,
108}
109
110pub(super) fn annotate_guards(store: &mut Store, execution_order: &[NodeId], completion: NodeId) {
111    // Execution position; a guard's condition node must run before the nodes
112    // it guards so the condition variable exists when the branch is taken.
113    // Pure nodes unreachable from the completion node are absent from the
114    // execution order and keep the zero sentinel — never read, since guard
115    // subjects are inputs of reachable nodes and inputs are deps.
116    let mut position: IndexVec<NodeId, usize> = IndexVec::from_vec(vec![0; store.node_count()]);
117    for (i, &id) in execution_order.iter().enumerate() {
118        position[id] = i;
119    }
120
121    let mut consumption: IndexVec<NodeId, Consumption> =
122        IndexVec::from_vec(vec![Consumption::None; store.node_count()]);
123
124    for &id in execution_order.iter().rev() {
125        // Effects always run; the completion node is consumed by the engine.
126        let eligible = !store[id].op.is_effectful() && id != completion;
127        if eligible
128            && let Consumption::OnlyUnder(x) = consumption[id]
129            && position[x] < position[id]
130        {
131            store[id].guard = Some(x);
132        }
133
134        // What this node's `Always` reads contribute to its producers:
135        // `Some(x)` when the read is unobservable under `non_empty(x)`
136        // failing because the node itself is guarded on `x` (rule 2), `None`
137        // otherwise.
138        let own = store[id].guard;
139
140        // Push onto the value edges — read from operation inputs, never from
141        // `deps`, so an ordering-only edge never looks like a consumer.
142        for (input, read) in store[id].op.input_reads() {
143            let contribution = match read {
144                // Rule 1: read only while iterating `row_input`'s rows, so
145                // unobservable whenever `row_input` is empty — regardless
146                // of the node's own guard.
147                InputRead::PerRowOf(row_input) => Some(row_input),
148                InputRead::Always => own,
149            };
150            consumption[input] = match (consumption[input], contribution) {
151                (Consumption::None, Some(x)) => Consumption::OnlyUnder(x),
152                (Consumption::OnlyUnder(prev), Some(x)) if prev == x => {
153                    Consumption::OnlyUnder(prev)
154                }
155                _ => Consumption::Observed,
156            };
157        }
158    }
159}
